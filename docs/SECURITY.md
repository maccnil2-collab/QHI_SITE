# Безопасность

- Не хранить пароли, токены, приватные ключи и реальные персональные данные в репозитории, исходниках, фикстурах или логах. `.env` игнорируется; использовать отдельный секрет-менеджер в развёртывании.
- Валидация входов выполняется схемами Pydantic; SQL — только параметризованный через SQLAlchemy.
- Пароли (при внедрении identity) хранить только через современный парольный KDF; токены ограничивать по сроку, сессии отзывать.
- Применять минимальные роли, проверку доступа на сервере, rate limiting для входа и аудит административных изменений.
- CORS ограничивать известными origin; cookie сессии — HttpOnly/Secure/SameSite; CSRF-защита для cookie-аутентификации.
- Загружаемые файлы ограничивать типом, размером и проверять; не доверять пользовательским URL и именам файлов.
- Не выполнять платежи, юридически значимые действия или уведомления без явного бизнес-процесса и владельческого подтверждения.
- Ошибки клиенту не должны раскрывать SQL, секреты, локальные пути или стек-трейсы.
- Для production предусмотреть TLS, резервное копирование с проверкой восстановления, обновления зависимостей и мониторинг.
